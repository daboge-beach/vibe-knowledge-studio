# 换电脑后继续制作

1. 克隆仓库到空间充足的位置，按README安装环境；Windows本工作机使用E盘，新电脑按实际磁盘选择，不必复刻盘符。
2. 读根目录AGENTS、总规范、风格、交接、节奏和核查文件；用project.json选取真实可运行工程，不能从旧ZIP或history选择“最新”。
3. 执行prepare，再执行check all；抽看你要修改的关键动作。需要原配乐时，从你自己的授权备份导入最终混音，并登记许可和哈希。
4. 新任务在独立分支或独立工程副本进行，不改另一个会话正在使用的目录。修改前记录父版本；共用字幕、事实、音乐变化检查两画幅。
5. 先导出前段和最难动作，逐点比源帧；再全片。源检查、最终MP4检查、完整观看/试听、平台UI和用户验收分别记录。
6. 收工前用git diff/status检查，只提交源码、规范和必要记录。自备音频、最终视频、私有素材、.outputs单独同步到你的备份位置，不能误认为git push会上传它们。

典型命令（在仓库根目录）：

```shell
git pull --ff-only
git switch -c episode-05-work
python tools/studio.py list
python tools/studio.py check all
git status --short
git add README.md project.json planning episodes tools docs
git diff --cached --stat
git commit -m "Update episode production sources"
git push -u origin episode-05-work
```

提交范围按实际任务调整，不使用忽略规则强制上传音乐或凭据。不要把尚未授权的素材放入Git历史；之后删除文件也不会自动删除已公开历史。

根目录 `project.json`新增单集时，登记独立画幅、时长、fps和资源，不继承旧片的固定130秒、音轨摘要或通过项。第五六集目前只有策划，需先复制任务单完成内容和双画幅分镜。现有工具面向前四集工程；新引擎接口不同需要适配并重新验证。

环境故障：字体下载失败先检查网络或本机代理，勿关闭证书校验；可把锁定摘要一致的两款字体放到`.cache/fonts/`再prepare。Chromium未安装则使用安装脚本；也可显式选择已有Chrome。FFmpeg缺失先安装并确保ffmpeg/ffprobe可调用。
